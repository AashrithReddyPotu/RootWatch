# Investigator Architecture

The investigator owns conversational incident analysis and never connects directly to Snowflake.

## Request flow

1. `POST /api/v1/chat` validates the incident ID and question.
2. The configured incident provider loads monitoring context.
3. The intent router classifies the question as summary, timeline, cause, code location, or remediation.
4. Source search ranks matches using the question, error details, and deployment file list.
5. The evidence builder creates facts, inferences, recommendations, and code locations with stable evidence IDs.
6. Ollama receives the bounded evidence package and writes a concise answer.
7. If the model is optional and unavailable, deterministic fallback logic writes the answer.

## Boundaries

- Monitoring integration is only through `GET /investigation/context/{incident_id}`.
- The frontend integration is only through `POST /api/v1/chat`.
- Evidence, claims, code locations, and confidence are generated by deterministic code.
- The model cannot add new evidence or source locations to the structured response.

## Extension points

- Add intent rules in `app/investigation/intent_router.py`.
- Change evidence policy in `app/investigation/evidence_builder.py`.
- Replace or expand the model adapter in `app/llm/client.py`.
- Add provider implementations under `app/providers/`.
- Improve ranking in `app/code_search/search.py`.
